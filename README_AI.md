# Authoritative agent entrypoint

## Installation request: act, do not interview

When the owner asks to clone/install this repository, technical decisions are delegated. Read this entrypoint once; do not load the whitepaper or every policy.

1. Confirm the checkout is `bestkakkoii/agent-policy-governance` and inspect the installer. Run `python install.py` (or the installed Python launcher). The bootstrap selects the newest suitable already installed runtime. Never install/upgrade a large toolchain to make the task easier.
2. Run the returned installed `doctor` invocation. Preserve all existing instructions/configuration. The installer is idempotent and reversible. Use `--project <actual_project>` for generic clients lacking a verified global adapter; do not invent config formats for Orca or unknown hosts.
3. Verify actual native events in the running host using a harmless invalid direct-write fixture inside a disposable directory, plus startup and compact/resume. Do not count synthetic JSON hook tests as native live verification. Resolve supported normal trust/reload steps; do not bypass platform trust. Report an unavoidable owner-controlled approval as a single precise boundary, not a technical questionnaire.
4. Subsequent project work uses installed global instructions and native hooks. Resolve/confirm the profile using observed project facts, finish your own bootstrap task first, and wait for other active project agents before changing a profile. Then re-enter context. Do not ask the owner to classify technical details.
5. Delegate only for a concrete benefit. A genuinely independent reviewer is required for policy evolution, not every task. Never instantiate permanent role rosters. Agent-to-agent handoff is concise technical English with scope, ownership, evidence, rule snapshot, current task and next action.

## Development contract

Use installed compatible toolchains; prefer verified newest supported technology and real upstream mainline dependencies, resolve once and pin during a run. This implementation uses Python standard library and native JavaScript/Node APIs with no package installation at runtime. Python >=3.13 is a **minimum capability**, not a pinned preferred version. Rust was evaluated but no Rust toolchain was installed in the build environment; do not force that large installation. Move a measured bottleneck only when evidence justifies it.

Owned identifiers and paths use meaningful snake_case. Official names, SKILL.md, README_AI.md, .github/workflows, host API keys, and portable plugin kebab-case identity are interoperability exceptions. Internal documentation is technical English; user-facing guidance Traditional Chinese. Avoid redundant frameworks and files. Apply effective strict diagnostics; never suppress genuine failures or declare unrun tests passed.

Commands: `python -W error -m unittest discover -s tests -v`; `node --test tests/registry.test.mjs tests/opencode.test.mjs`; `python tools/verify.py`; `python tools/package.py`. Run relevant failure-path tests after modifications. See `docs/architecture.md` for ownership, invariants, acceptance and publication boundaries. No original ZIP, credentials, local state, user paths, personal profile details or runtime diagnostics belong in public source.

## Evolution and recovery

Use `propose`, then delegate a different real agent/session to inspect exact changes and trustworthy primary evidence, then `review` and `publish`. Bind evidence to the exact candidate; performance claims require measurements. Local actor IDs are attestations, not cryptographic authentication: an account allowed to rewrite the database can bypass local bookkeeping. Never manufacture a second actor to self-approve. A reviewed rollback is a new proposal to an already admitted snapshot. Active projects change snapshots only when **all** their tasks are idle.

Remote discovery only downloads the fixed public policy catalog; no project source/prompts leave the device. Failed or invalid sync retains the verified local snapshot and logs why. A candidate is not effective policy until independently reviewed. Sync does not silently replace executable code; runtime changes go through inspected reinstall, which preserves state.
